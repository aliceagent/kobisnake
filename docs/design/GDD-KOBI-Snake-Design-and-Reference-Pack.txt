1. ORIGINAL GAME CONCEPT
======================================================================

GAME NAME:
KOBI Snake

ORIGINAL CATEGORY:
Arcade / Snake

ORIGINAL IDEA:
Two snakes compete for food without hitting walls or each other.

CONTROLS:
WASD vs Arrow Keys

REPLAY VALUE:
Classic replayability, shrinking arena, special food, speed changes.

OVERALL DIRECTION:
KOBI Snake is intended to be a modern, highly replayable browser-based Snake game,
built to work with one or two players on the same keyboard. It should require no
online content, no mouse during actual gameplay, and should be approachable enough
that an 11-year-old developer can understand, modify, and continue building it.

The major visual experiment is to use Three.js or another browser-based 3D engine
while preserving a top-down / bird's-eye gameplay view.

2. DISCOVERY BRIEF
======================================================================

PURPOSE

We want to design and build a small, highly replayable web-based game called KOBI Snake.

The game is inspired by the fundamental simplicity of classic Snake, but we do not
want to simply remake Snake with prettier graphics.

The goal is to create something that:

- An 11-year-old can realistically understand, modify, and continue coding.
- Is immediately fun.
- Can be played for a few minutes or repeatedly for much longer sessions.
- Works entirely in a web browser.
- Requires no mouse during gameplay.
- Supports one-player and/or local two-player gameplay.
- Can be played by two people sharing one keyboard.
- Has no multiplayer servers.
- Has no online content or dependency on live services.
- Uses a top-down / bird's-eye-view perspective.
- Uses 3D graphics, preferably with Three.js.
- Feels much more visually polished and dimensional than a normal browser Snake game.
- Has enough randomness, strategy, progression, competition, and variation to retain long-term play value.

This discovery process was intentionally designed not to lock every mechanic in too early.

CORE GAME CONCEPT

At the simplest level:

KOBI Snake is a modern 3D top-down Snake game in which one or two snakes move around
an arena, collect food or other objects, grow, avoid danger, and try to survive or
defeat their opponent.

Classic Snake should be treated as the foundation rather than the final mechanic.

Mechanics considered during discovery included:

- Snake growth
- Food
- Collision
- Arena hazards
- Speed changes
- Special food
- Power-ups
- Shrinking arenas
- Temporary abilities
- Different snake behaviors
- Different arena configurations
- Competitive two-player mechanics
- Survival modes
- High scores
- Unlocks
- Increasing difficulty
- Procedurally generated situations
- Risk/reward choices
- Combos
- Environmental effects

PRIMARY DESIGN PRINCIPLE

The game should be:

"Easy to understand in 10 seconds, difficult to master after 100 games."

Avoid unnecessary complexity.

Ideally:

1. Player presses Start.
2. Snake begins moving.
3. Player understands almost immediately what to do.
4. Interesting situations gradually emerge from the mechanics.

The complexity should come from the interaction between simple systems rather than
lots of buttons or rules.

PLAYER AGE / DEVELOPMENT CONSTRAINT

The game is being designed with an 11-year-old programmer in mind.

Therefore, avoid designing mechanics that require enormous amounts of:

- Animation work
- Content creation
- Backend development
- Complicated AI
- Networking
- Physics simulation
- Asset management
- Advanced shaders
- Procedural generation algorithms

Favor understandable game variables such as:

snake.speed
snake.length
snake.score
food.type
food.value
arena.size
powerup.duration
game.difficulty

over overly abstract architectures.

PLATFORM

Target:
Desktop web browser

Possible technology:

- HTML
- CSS
- JavaScript
- Three.js
- Web Audio API
- LocalStorage

There should be:

- No required account
- No login
- No server
- No database
- No matchmaking
- No API calls
- No streamed assets
- No advertisements
- No online leaderboard requirement

Ideally, the game can continue working if the computer has no internet connection

CONTROLS

Player 1:
W / A / S / D

Player 2:
Arrow Up / Arrow Left / Arrow Down / Arrow Right

During discovery, we considered whether players should have an additional action button
for boost, dash, brake, shield, attack, dropping obstacles, or activating stored power-ups.

The final direction so far is to keep direction controls primary, while power-ups remain
optional and simple.

CAMERA & PERSPECTIVE

The game should use a top-down bird's-eye-view camera.

However, it should not look like a flat 2D game.

The world should feel like a miniature 3D arena viewed from above.

Possible camera characteristics:

- Slight perspective rather than perfectly orthographic
- Enough tilt to see sides of objects
- Shadows under snakes and objects
- Visible depth and thickness
- Smooth camera movement
- Small camera reactions to important events
- Slight zoom during dramatic moments

Gameplay must remain extremely readable.

VISUAL DIRECTION

The final chosen direction is:

Bright LEGO-inspired building-block toy style.

The entire game should feel built from colorful modular plastic construction pieces.

Everything should share the same physical visual language:

- Snake
- Food
- Arena
- Walls
- Hazards
- Power-ups
- Particles

- Menus

The interface should feel like it belongs to the same toy world as the game.

MOVEMENT OPTIONS CONSIDERED

A. Classic grid movement
B. Smooth analog-style movement
C. Hybrid

Chosen:
Hybrid.

The snake logically moves on a grid and makes clean 90-degree turns, but its motion is
visually interpolated so it glides smoothly rather than snapping cell by cell.

GAME MODES CONSIDERED

- Classic
- Endless Survival
- Battle Snake
- Duel
- Co-op Survival
- Time Attack
- Challenge Mode

Chosen initial priority:
Two-player Battle Snake first.

Single-player should come later after the two-player core is fun.

3. CORE DESIGN PRINCIPLES
======================================================================

1. SIMPLE TO LEARN
The rules should be understandable almost immediately.

2. SHORT, REPLAYABLE ROUNDS
A loss should naturally produce:
"Again!"

3. PLAYER SKILL MATTERS
Randomness and power-ups can add variety, but should not make the game feel unfair.

4. TWO-PLAYER FUN IS THE PRIMARY MVP TARGET
The game should be designed around two people physically sharing one keyboard.

5. THE CLOSING LASER ARENA IS THE SIGNATURE HOOK
The arena forces a climax instead of allowing players to avoid each other forever.

6. 3D PRESENTATION SHOULD IMPROVE FEEL, NOT HURT READABILITY
Three.js is for character, depth, lighting, and atmosphere, not unnecessary complexity.

7. SYSTEMS OVER HANDCRAFTED CONTENT
Replayability should come from interaction between simple systems rather than hundreds
of manually built levels.

8. BUILD IN LAYERS
Prove that the movement and battles are fun before investing heavily in art.

5. COMPREHENSIVE GAME DESIGN & BUILD SPECIFICATION
======================================================================

GAME VISION

KOBI Snake is a modern local multiplayer reimagining of classic Snake.

The fundamental gameplay remains immediately understandable:

- Snakes constantly move
- Players steer them around an arena
- They collect items
- Snakes grow
- A snake dies when its head hits something deadly

The major twist is that every match has a natural climax.

During the final 30 seconds of a 90-second round, four deadly laser walls surrounding
the square arena begin closing inward.

The available space becomes smaller and smaller, forcing the snakes together until
somebody crashes.

The game should feel like:

"Classic Snake, but turned into a fast, colorful 3D battle game."

PRIMARY DESIGN GOALS

SIMPLE
Players should understand the basic rules almost immediately.

COMPETITIVE
Two people sitting at the same keyboard should constantly create funny, tense,
exciting situations for each other.

REPLAYABLE
Rounds are short enough that losing naturally produces:
"Again!"

VISUALLY DISTINCTIVE
The game should not look like a normal HTML Snake game.

EXPANDABLE
Architecture should allow future:
- Power-ups
- Snake colors
- Arenas
- Game modes
- Cosmetics
- Music
- Challenges

UNDERSTANDABLE TO A YOUNG DEVELOPER
The project should stay approachable.

MAIN GAMEPLAY HOOK

Closing Laser Arena

Every standard round lasts approximately 1 minute 30 seconds.

For roughly the first minute:
Players have the full arena.

When the timer reaches 30 seconds remaining:
The endgame begins.

Four laser boundaries on the top, bottom, left, and right gradually move inward.

The lasers are deadly.

As the walls move inward:
- Arena becomes tighter
- Players encounter each other more often
- Long snakes become harder to maneuver
- Defensive play becomes less effective
- Match naturally builds toward confrontation

PERSPECTIVE AND CAMERA

Top-down / bird's-eye 3D camera.

Preferred:
Slight perspective angle rather than perfectly vertical.

Enough to see:
- Thickness of toy bricks
- Snake body depth
- Shadows
- Arena edges
- Laser structures
- 3D food
- 3D power-ups

Priority:
Gameplay clarity over cinematic flair.

Avoid:
- Extreme camera movement
- Large rotations
- Perspective distortion
- Effects that hide collision locations

======================================================================

MOVEMENT
- Does smooth grid movement feel responsive?
- Are turns accepted reliably?
- Does the snake ever feel like controls were ignored?

VISIBILITY
- Can each player instantly locate their head?
- Are red and blue readable under all lighting?

======================================================================
FINAL GUIDING PRINCIPLE
======================================================================

Do not add features merely because they are common in games.

Every mechanic should serve at least one of these purposes:

1. Make movement more satisfying.
2. Make two-player competition more exciting.
3. Make the closing arena more dramatic.
4. Give players a reason to play again.

Prefer:
Five simple systems that interact beautifully

over:
Twenty unrelated features

FIRST REAL MILESTONE:

Build two snakes.
Put them in a square arena.
Make movement feel excellent.
Make two people have fun trying to make each other crash.

Then add the closing lasers.

If those two things are fun together, KOBI Snake has a strong foundation.
